# 传送门隔离测试步骤

当前源码为 `0.1.5`。用户于 2026-11-08 确认本版 Live Wire 1.7.2 适配的隔离联测可用。原版发电机、Immersive Solar Arrays 1.2.15 和既有单人玩法在 `0.1.4` 于 2026-11-06 通过离线检查和用户验收，可按下列步骤回归。

C「雨夜归途」封面、原生新配方、传送耗电设置、可缩放四槽界面及 schema3 保存格式保持。全部游戏操作由你进行。B42.22.2 候选先做离线验证。后续实测请在独立、已验证可启动的 42.22.2 环境中使用普通视角，先查建造、四槽原电池、配对、传送失败退款和保存重进，再测独立 Live Wire 1.7.2。下文的旧桌面入口、停电模板与 Viewpoint 操作属于 B42.21 既有环境。

## 先进入停电模板

继续使用桌面原「传送门隔离测试」入口，在“载入”菜单选择 **`2026-11-06_Energy_Template`** 派生存档，不要误进原档 `2026-11-06_15-46-59` 来做停电对照。

模板派生自现有隔离测试世界，离线复制后修改该副本实际 `map_sand.bin` 的停电参数；它不是空白新世界，原世界文件与进度保留。复制源里已有的建筑、人物或物品会继承；本轮没有另造作弊角色，也没有替你预先摆放或开启发电机、太阳能设备。根据下面步骤自行摆放、连接和开启，需要时可由你使用原版调试工具准备物资或技能，本模组不发放道具。

进入后先检查室内灯和电器没有市电；同时确认附近没有开启的供电设备造成假阳性。如仍有市电或不确定自己进入哪个世界，先保留存档名、日期和截图，暂不把本次数据记为发电机或太阳能计费结果。

## 供电复查步骤

仅在隔离环境测试。旧供电模板的名单已追加 ISA。请从本次隔离实例新日志确认实际装载。太阳能测试需要该测试实例实际装载受支持的 **Immersive Solar Arrays 1.2.15 / 工坊3781944805**；从本轮部署回执确认测试入口和加载名单，不把正式档的已安装模组视为隔离版已加载，也不要为测试修改正式启用列表。本轮不声明兼容另一个 `[BETA]-Fix` 包。

1. **先测空／满电池免耗。** 确认无市电后摆放、连接并开启一台有燃油的发电机，使它覆盖传送门。先让门无电池，再装全部满电电池、仅损坏电池，确认附加传送门负载为零且没有该门额外扣油。有其他电器时，它们及发电机自身仍正常耗油；本步骤不是要求总油耗为零。传送锁定期间同样不充电、不收取门的充电消费。
2. **缺电门接燃油发电机。** 装入至少一块未满且完好的电池，确认管理界面来源为发电机。记录开始和结束游戏时间、门电量、原生发电机燃油升数、其他电器及面板附加负载和合计。默认 `GeneratorFuelConsumption=0.1`、整门充电速率0.5时，每游戏小时实际充入0.5满电等量，额外消费 **0.015 L**，不包含发电机基础与其他设备油耗；倍率改变时按 `0.15 L × 倍率` 计算。
3. **燃油不足与熄火。** 在隔离调试环境准备少量燃油，确认本次充入量受可用燃油限制，不会免费补满或把燃油扣成负数。手动关机、燃油耗尽及重新启动后检查来源和充电恢复；断电间隔不追补。
4. **ISA有电银行。** 先关掉普通发电机，在无市电的位置自行布置 ISA 太阳能板／有电的储能银行，按 ISA 自带面板确认银行储能大于零且已开启、覆盖到门。记录门电量、银行实际储能和其他负载；优先夜间或没有日照输入的可控条件下比较。门应显示太阳能来源，成功充电会减少选定银行的真实储能。不要把代理发电机燃油当作太阳能储能，也不要只看“连接电力”文字。
5. **ISA关闭／没储能。** 用接近耗尽的银行供电，确认只充入买得起的电量；银行关闭、耗尽或失去覆盖时停止，恢复后从当前时间继续，不制造电量。空槽、满电、损坏、锁定的免扣规则与普通发电机一致。
6. **重叠来源。** 让两台发电机、两个太阳能银行或发电机与太阳能重叠覆盖，确认同一次门充电只向选定的一个来源结算，没有重复扣费。室内市电优先的对照应在有市电的独立测试条件下做；不用为此改回停电模板或原档参数。有市电时不额外扣发电机燃油或太阳能储能。
7. **卸载与保存重进。** 离开至区域卸载或正常保存退出，重进后检查四槽原电池、名称、配对和能源数据；卸载及退出时间不补充电量、不补扣一段历史消费。继续测试传送及失败退款，确认传送耗电仍只从出发门已安装电池扣除。
8. **面板限制。** 本版是在面板显示额外传送门负载与合计，未向 Java 原生设备清单注册门。BGI 等仅读原生总负载的剩余时间估算尚未纳入这份独立消费，不用其倒计时单独判断是否扣费；以实际燃油／储能变化和本轮面板数据为准。

上述发电机与 ISA 路径在 `0.1.4` 通过完整离线检查和用户单人验收。结算参数和支持范围见[供电兼容说明](供电兼容说明.md)。

## Live Wire 1.7.2 验收

在启用 `SuQingPortals` 0.1.5 和 `batman_LiveWire` 1.7.2 的隔离存档中操作。先从该实例本次启动日志核对实际装载的版本，在停电区摆放已开启逆变器和连入同一网络的有电电池柜，关闭附近其他供电来源。记录门内原电池电量、实际电池柜储能、逆变效率及起止游戏时间。

1. **充电与扣量。** 在实际覆盖内开启门所在的设备回路，装入一块完好且缺电的电池。门应显示「Live Wire 储能」。优先在无风、无日照输入且无其他负载的受控条件下对比，另测一段门不充电的基线。根据实际增加的满电等量 `q` 计算门的柜侧附加耗电 `q × 0.30 ÷ 逆变效率` kWh。储能不足时，只充入扣除仿真用电预留后仍付得起的量。
2. **停止与恢复。** 分别关闭 Live Wire 的设备回路、关闭逆变器、移出覆盖或移走电池柜电池。门应停止依赖该网络充电。仅有太阳能、风能或水力发电而没有可用电池柜储能时也应暂停。恢复后从当前时段计量。
3. **零需求。** 用空槽、已充满、只有损坏电池以及传送锁定逐项复查，柜侧没有来自门的额外扣量。以柜内实际储能为准，Live Wire 瞬时负载和续航预测不会显示这份独立消费。
4. **重叠和备援。** 比较两个 Live Wire 网、独立发电机或 ISA 与 Live Wire 重叠的情况。每次门充电只使用一个来源，室内市电、可用独立发电机和 ISA 优先。再把备用机接入 Live Wire 网络，确认该网络和绑定的备用机不会被门独立扣储能或扣油。可移除绑定后重试。
5. **卸载和保存重进。** 离开直到门或储能柜卸载，再返回并保存重进。核对柜储能和门内原电池都被保留，卸载、断电和退出时段无补扣、无补充。复查普通发电机、ISA 及出发门扣电的传送规则。

## 界面与普通玩法复查

1. 从桌面「传送门隔离测试」正常启动，本轮供电测试优先按模板收据名称选择停电派生档；原隔离档 `2026-11-06_15-46-59` 保留，可用于此前界面和普通玩法复查。右键门体打开管理界面，确认门名无 `$s` 残留、电量和耐久只显示一个百分号。
2. 检查顶部电源状态、充电状态和速率。室内有市电、发电机覆盖、断电时分别查看；来源不能可靠确认时应显示区域供电／来源未确认，而不是编造发电机。电源已连接不等于正在充电：无电池、满电、损坏或事务锁定均应明确说明。
3. 拖动窗口右下角或底部调整大小，检查按钮与卡片不重叠。普通1366×768和1920×1080目标为一屏展示；小窗口／大字体可出现必要滚动。传送按钮应始终在固定底部，操作区不被遮挡。
4. 右键普通地面和传送门，确认没有领取道具选项，沙盒传送门页也没有发放物资开关。模组不会自动发物品；旧角色原有物品保持。测试物资和技能需要时由你自己使用原版调试工具准备。
5. 保存退出重进，检查四槽原电池、电量、名称与配对；分别在普通视角和Viewpoint检查四朝向门体、底座、电池仓和右键命中。

## 玩法与新配方

每门消耗小金属板8、金属管4、电线8、电子零件16、高端相机1、手持对讲机1；要求电工4级、焊接3级。螺丝刀、焊枪和焊接面罩保留，不额外扣焊枪燃料或焊条。接受原版六种手持对讲机，收音机和大型电台不替代。汽车电池建好后另装，最多四块。

先检查技能不足时原生入口禁用，再设置技能或练级后取消一次建造并完成一门；确认只扣一套六种材料，三件工具保留，已有门不补扣材料。

沙盒「蘇清的传送门」页只有两项：单次传送耗电量0.5～4、默认2；整门每游戏小时充电量0.05～4、默认0.5。本轮不改写现有存档的沙盒值；旧档缺失新耗电字段时用默认2。

可新建隔离自定义沙盒，分别选耗电0.5和4；四块满电应分别显示8次和1次，实际出发端每次分别扣0.5和4，接收端不扣电。进行中改设置不应改变原票据的结算或退款。

## 传送与充电

建两座门并命名配对。先只给A门安装电池，让B门保持空电池且无电；从A去B应成功，仅A扣设定电量。给B装电池后再测返回。

默认整门每游戏小时充入0.5等量，不是四槽各充0.5。市电要求室内；普通发电机和受支持的太阳能银行按本轮供电结算规则消费能源。断电停止，区域卸载／退出后不追补；能源不足时限制实际充入量。

测试较远未加载地点、终点出口受阻及失败退款；恢复提示出现时用右键重试恢复，仍失败时保留日志，正常保存退出再进入。传送准备中反复点击不应重复扣费或装卸。

## 范围与反馈

所有游戏内操作由你完成。本模组当前仅支持单人角色和随身物品，不支持车辆、拖挂或联机。Live Wire 适配的单人游戏内验收以本轮实测反馈为准。

只使用隔离目录。反馈优先给失败步骤、供电／两端电量／配对状态及截图，并保留隔离 `data/console.txt` 与 `data/Logs`。异常时不要直接删除门或清理存档。
