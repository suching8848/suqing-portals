# 传送门供电兼容说明 / Portal power compatibility

源码版本为 `0.1.5`，目标为 B42.21 单人游戏。用户于 2026-11-08 确认该版在 B42.21 单人隔离联测中可用。上一版 `0.1.4` 的原版发电机与 ISA 路径于 2026-11-06 通过离线检查及用户单人验收，工坊条目 `3834693880` 已核验为公开的 `0.1.5`。

## 中文

### 供电与计费

传送门只在门所在区域已加载、有可核实的当地供电、至少一块完好电池未满且没有传送锁定时充电。室内市电优先，其余情况选定一个覆盖来源结算；重叠覆盖不代表向所有来源同时扣费。只有成功保存到原电池中的实际充入量产生费用，能源不足时限制充入量。空槽、满电、损坏电池、锁定、卸载和断电都不收取本门的额外充电消费；离线和卸载间隔不追补。

传送仍从出发门四槽内的电池扣除已设置的0.5～4满电等量，默认2；接收门不要求当地供电。充电消费与传送扣电是两个过程，不改变原电池、配方或 schema3 保存格式。

### 普通发电机

本版按实际充入量独立结算燃油，不改写原生总负载。标定采用原版汽车电池充电器：其0.05 L/小时负载对应每小时充入1/6满电等量，因此每满电等量计0.3 L，再乘沙盒 `GeneratorFuelConsumption`。

| 实际充入量 | 额外燃油消费 |
| --- | --- |
| 0.5满电等量 | 0.15 L × 发电机油耗倍率 |
| 1满电等量 | 0.30 L × 发电机油耗倍率 |
| 4满电等量 | 1.20 L × 发电机油耗倍率 |

默认整门充电速率为0.5满电等量/游戏小时，有足够可用燃油和待充电电池时额外消费0.15 L/游戏小时乘倍率。**原版默认 `GeneratorFuelConsumption=0.1`，因此默认实际额外消费为0.015 L/游戏小时**。发电机自身和其他设备仍保留正常油耗；表中数值仅为传送门充电增加的部分。不是每槽都收取整门费用，也不会对同一次充电向多台发电机重复结算。

### Immersive Solar Arrays

本轮针对本机安装的 **Immersive Solar Arrays 1.2.15**，工坊 `3781944805`。这是可选兼容：未安装 ISA 时，普通发电机路径仍可使用。不自动订阅、安装或向个人正式名单增加任何模组。

从覆盖门的受支持电池组中选定一个银行，按成功充入量扣除该银行的真实原电池储能。ISA 用于覆盖供电的代理发电机不能按普通燃油机扣费。管理界面显示太阳能来源；仅有“当地通电”而无法正确识别和结算储能时，不能据此免费补满传送门电池。

本轮换算跟随 ISA 现有 `DrainCalc` 规则。设实际充入量为 `q` 个满电等量，未乘沙盒油耗倍率的燃油等价为 `rawFuelEq = q × 0.3`：

| ISA模式 | 扣除的ISA储能 |
| --- | --- |
| `DrainCalc = 2` | `rawFuelEq × 800 × GeneratorFuelConsumption` |
| `DrainCalc = 1` | `rawFuelEq × 920`，不另乘发电机油耗倍率 |

上表是 ISA 内部储能单位，不把它称为千瓦时或汽车电池数量。ISA 自己的太阳能输入、其他设备负载、银行配置与保存流程继续使用上游逻辑。本模组不覆盖 ISA 的 `updateDrain`，也不把同一消费既加进原生总负载又独立扣一次，避免双扣。接口、供电来源及银行不可核实时拒绝该桥接，不凭当地通电免费充电；未知ISA版本、`ISA-Fix`组合及不受支持模式不会套用1.2.15结算。

另一个工坊包 **Immersive Solar Arrays [BETA]-Fix / `3592668881`** 不是本轮支持对象。一个包已安装或同名功能存在，不代表本适配已经在该分支通过。其他版本及修改分支需重新核对接口和验证。

### Live Wire

支持已启用的 **Live Wire 1.7.2**，工坊 `3821807453`，Mod ID `batman_LiveWire`。先检查室内市电、独立燃油发电机及受支持的 ISA 来源。它们都不可用时，门才能由一个正在实际供电的 Live Wire 网络充电。逆变器和至少一个有可用储能的电池柜须已加载，门所在方格须在实际覆盖内且设备回路开启。

逆变器输出侧采用固定标定，每满电等量按 `0.30 kWh` 计，充入 `q` 个等量用 `q × 0.30 kWh`。电池柜扣量为 `q × 0.30 ÷ 逆变效率` kWh。门在默认速率、储能充足且持续供电时每游戏小时充入 0.5 等量，输出侧用量为 0.15 kWh。门只使用选定电池柜的可用储能，先为至少一个 Live Wire 仿真步的普通负载、泵和逆变器空耗保留电量。柜侧只扣除成功写入并保存到门内原电池的对应电量。

充电只取用真实电池柜里已储存的能量。没有可用柜储能、设备回路关闭、逆变器停供或版本不受支持时暂停这条路径。连接 Live Wire 备用发电机的网络也不参与，已绑定的备用机不会作为本桥接的独立燃油来源。卸载、断电和退出期间不追补。该扣量独立于 Live Wire 仿真的用电功率清单，实际电池柜储能会减少。Live Wire 的即时负载、断路器、续航预测和负载磨损仍以自身仿真的用电清单为准。

### 面板、估算与验收边界

发电机面板通过包装显示本模组的额外负载及合计；**没有把传送门注册进 Java 原生设备清单**。这一显示能力不等于修改了原生负载 API。BGI 等只使用原生总负载的剩余时间估算尚未纳入传送门独立消费，可能偏长；实际能源变化优先于这些估算。

`0.1.4` 的完整 `validate_release` 检查涵盖 `native_power_api`、`power_settlement`、`power_display`、`isa_power` 与 `isa_native_interop`。用户于 2026-11-08 确认 `0.1.5` 的 B42.21 单人隔离联测可用。[用户测试步骤](用户测试步骤.md)

原桌面隔离入口可用于发电机和 ISA 对照。停电模板准备完成后按模板收据名称选择 `2026-11-06_Energy_Template` 派生档；它离线复制现有隔离测试世界后修改副本的实际停电参数，不是空白新世界，原档不改写。模板没有另造作弊角色或预摆、开启供电设备，复制源已有内容会继承；由用户先确认室内无市电，再自行准备并摆放发电机、太阳能设备，依次验收空／满电池免耗、普通燃油充电、ISA储能充电、关闭／耗尽、重叠来源及保存重进。

## English

### Supply and settlement

Charging requires a loaded gate, a verified local provider, at least one healthy battery with room for charge, and no active transfer lock. Indoor grid supply takes priority. Otherwise one covering provider is selected; overlapping providers do not all pay for the same charge. Only energy actually and successfully stored in the original batteries creates a debit, and available source energy limits that charging step. Empty slots, full or damaged batteries, locks, unloaded gates and lost power create no portal charging debit. Unloaded and offline time receives no catch-up credit or debit.

Travel still spends the selected 0.5–4 full-battery equivalents, default 2, from departure batteries only. Arrival needs no local power. Charging settlement does not change the recipe, original items or schema3 storage.

### Fuel generators

This release settles fuel independently without modifying the native total load. The native charger calibration is 0.05 L per game hour for 1/6 full-car-battery equivalent per hour: 0.3 L per full equivalent, multiplied by sandbox `GeneratorFuelConsumption`. At a total gate rate of 0.5 equivalent/hour, continuous demand adds 0.15 L per game hour times that multiplier. The native default multiplier is 0.1, so **default additional consumption is 0.015 L per game hour**. The generator and other appliances retain their normal consumption. A gate does not charge this full rate once per slot or debit every overlapping generator.

### Optional Immersive Solar Arrays integration

The target is installed **Immersive Solar Arrays 1.2.15**, Workshop `3781944805`. Ordinary generator support does not require ISA, and this integration does not subscribe, install or change the personal enabled list.

One covering, supported battery bank pays from the real stored energy of its original batteries; ISA's supply proxy is not treated as a fuel generator. Management identifies solar supply. An electricity flag alone cannot justify free charging when the bank or settlement interface cannot be verified. Unknown ISA versions, ISA-Fix combinations and unsupported modes are rejected rather than using the 1.2.15 bridge.

For `q` full-battery equivalents actually stored, `rawFuelEq = q × 0.3`. ISA `DrainCalc = 2` debits `rawFuelEq × 800 × GeneratorFuelConsumption`; `DrainCalc = 1` debits `rawFuelEq × 920` without another fuel multiplier. These are ISA internal energy units, not a kWh claim. ISA retains its own generation, other-appliance drain, settings and persistence. The portal does not override `updateDrain` or insert its independently settled debit into native total load as well.

The separate **Immersive Solar Arrays [BETA]-Fix**, Workshop `3592668881`, is not supported by this round. Other versions or modified branches need renewed interface review and verification.

### Live Wire

The optional integration targets **Live Wire 1.7.2**, Workshop item `3821807453`, mod ID `batman_LiveWire`. Indoor mains, independent fuel generators and supported ISA sources take priority. A Live Wire gate charge selects one network with a loaded inverter that is actively supplying power, a loaded cabinet with available stored energy, and an enabled appliance circuit covering the gate.

The inverter output uses a fixed calibration of `0.30 kWh` per full-battery equivalent, so storing `q` equivalents costs `q × 0.30 kWh`. The cabinet debit is `q × 0.30 ÷ inverter efficiency` kWh. At the default rate with sufficient continuous supply, the gate stores 0.5 equivalents per game hour and uses 0.15 kWh at the output. The gate draws only from the selected cabinet's available storage, leaving a reserve for at least one Live Wire simulation step of ordinary loads, pumps and inverter idle draw. The debit settles only the amount successfully saved to the gate's original batteries.

Charging draws from existing storage in real cabinets. An unavailable cabinet, a disabled circuit, an inverter that has stopped supplying power, or an unsupported version pauses this path. Networks with a linked Live Wire backup generator are ineligible, and a linked backup generator is excluded from the bridge's independent fuel path. No charging time accrues during unloading, outages or exits. This debit is separate from Live Wire's simulated load list. Actual cabinet storage decreases. Live Wire's load display, breaker, runtime estimates and load-related wear still use its own simulated demand.

### Display and verification limits

A generator-panel wrapper displays additional portal demand and the combined total. The portal is not registered as a Java-native appliance. BGI and other remaining-time estimates based only on native total load do not yet include this independent drain and may overestimate duration.

The user accepted `0.1.5` in the B42.21 single-player isolated setup on November 8, 2026. [User test steps](用户测试步骤.md)

Use the original desktop isolated entry for the generator and ISA comparisons. Once the outage template is prepared, select the `2026-11-06_Energy_Template` derivative using the exact save name in its receipt. This is a copy of the existing isolated test world with the copy's actual outage parameters changed, not a new empty world; the original save is preserved. No new cheat character or preplaced/activated power equipment is prepared. Inherited world contents remain. The user first confirms indoor appliances have no grid power, then places and enables the required generator/ISA equipment and tests empty/full batteries, normal fuel charging, solar storage charging, shutdown/depletion, overlapping providers and save/reload.
