# 蘇清的传送门 / SuQing's Portals

工坊条目：[已上传并核验的私有条目](https://steamcommunity.com/sharedfiles/filedetails/?id=3834693880)。源码仓库：[suching8848/suqing-portals](https://github.com/suching8848/suqing-portals)。2026-11-06已完成私有上传与原生内容读回；未公开，游戏内验收状态不变。

版本：0.1.3-lua-test.2。适用：当前核验的 B42.21 分支、单人测试。Mod ID：`SuQingPortals`。传送门本身使用纯 Lua，不需要自带 Java 组件；Viewpoint 为可选视角适配。

0.1.3采用用户确认的新配方：每门8小金属板、4金属管、8电线、16电子零件、1高端相机和1手持对讲机；电工4级、焊接3级，保留螺丝刀、焊枪和焊接面罩。已有门与配对不变，建成后的汽车电池仍另装。

当前版修正中英参数和百分号显示，提供单次传送耗电（默认2、范围0.5～4）及整门充电速率（默认0.5、范围0.05～4）两项沙盒设置。管理窗口可缩放，四槽采用紧凑布局，显眼显示电源连接、可识别的来源和充电状态；常规屏幕尽量一屏显示，小屏或大字体按需滚动。领取道具功能和对应测试开关已移除。游戏内验收仍由用户完成。

test.2修复右键报错：沿用原版`PickThumpable()`直接取得门对象，避免将Java的`ClickObject`结果当作Lua表读取。电池保存格式与玩法不变，可继续原隔离测试档。

这是独立主模组的隔离测试候选，包含中英文本、原生建造入口、专属管理界面、普通视角贴图和可选 Viewpoint 三维模型。源码位于 `E:\code\suqing-portals`；个人正式环境未部署本模组。

## 玩法

- 建造两座固定门，右键门体打开管理界面，分别命名并从列表选择另一座门完成双向配对。
- 每座门有四个专用汽车电池槽，接收原版 `Base.CarBattery1/2/3`。右键门体管理、放入或取出电池，操作通过原生动作队列与邻接检查执行。
- 原电池保存在门的原生内部存储中，由游戏原有存档机制保留身份、耐久、电量、名称及自定义数据。Lua 隐藏该存储的普通容器按钮，排除附近制作材料，并阻止普通拖放／转移动作；玩家通过四槽界面操作。没有传送门 JAR、Java 反射或额外 Java 许可步骤。任意第三方直接扫描世界物品的行为不在这些原生界面拦截范围内。
- 每次传送只从**出发门**扣除沙盒设置的电量，默认两块满电汽车电池等量，可调0.5～4。四块全满在耗电0.5时可传送8次、耗电2时2次、耗电4时1次；界面按当前实际设置计算。电池不会被消耗成材料。
- **到达门不需要电池，也不需要当地供电。** 要从到达门返回，仍需该门有足够出发电量。
- 当门所在区域实际加载且有当地电力时给已安装电池充电。市电要求室内房间；发电机遵循原版当地覆盖和室外供电规则。
- 默认整座门每游戏小时充入 `0.5` 块满电等量，四块空电池充满共需八游戏小时。默认耗电2时，补回一次传送消耗需四游戏小时。可在沙盒中调整充电速率 `0.05～4`，该数值是整门总速率。
- 未加载、退出游戏、未知供电和失去电力的时间不会补充电量。**本测试版没有将充电额外负载计入原生发电机油耗或设备清单。**
- 门体按四个槽位的实际空满状态显示，对应十六种组合；例如只装第2和第4槽时，外观也显示这两个位置。四个朝向共64张标准 `128×256` 图片与对应 Viewpoint 绑定。修复旧版图片额外128像素透明区导致的下移，保留门体比例与原世界坐标。
- 管理界面显示门名、配对目标、可传送次数、各槽电池名称／耐久／电量、当地供电及可识别来源、充电状态和速率、绑定／解绑、传送及禁用原因。支持拖动窗口边缘缩放，四槽2×2紧凑排布，传送按钮固定在底部；较小窗口或较大字体才回退滚动。

建造每座门需要8块小金属板、4根金属管、8根电线、16份电子零件、1台高端相机、1台原版手持对讲机；要求电工4级、焊接3级。完好的螺丝刀、焊枪和焊接面罩作为工具保留，本版不额外扣焊枪燃料或焊条。汽车电池在建成后另装。通过原生建造逻辑扣料，取消建造不另扣料。

## 范围与恢复

支持同一世界内的人物和随身物品传送；不支持车辆、拖挂或联机。小型门内的汽车电池可反复取出与充电。固定门的拆除会解除配对，释放原电池；一般家具搬运不属于本版支持流程。0.1.0旧门就地接管原存储，保留位置、身份、配对和原电池；异常数量、杂物、损坏数据或未完成传送会阻止迁移并保留原存储，使用管理界面的恢复操作处理。

test.1更新前，原隔离测试档经只读检查为0.1.0保存格式；之后已由用户加载纯Lua版，当前进度继续保留。若另有在0.1.1 Java版中安装了电池的存档，纯Lua版不会解码、清空或仿造其中物品：需要先在对应旧版及其备份环境中取回电池，保存后再升级。0.1.1空门可以迁移。

传送期间保存原有移动/穿透/隐身标志，临时保护加载过程；核实目标门身份和出口地面、阻挡、车辆、火及生物后才完成传送。失败会返回源位置并用原电池票据退款。源端尚未重新加载或原电池被外部移走时保留恢复记录，不伪造电池或宣称退款成功；右键可重试恢复，保存重进也会继续核查。

世界全局数据、人物文件及区块不是跨文件原子事务，极端断电或损坏存档的一致性尚不能保证。此限制与游戏内远距离加载、异常恢复、视角定位等均需用户测试。离线通过不代表实际游戏验收通过。
